# Техническое задание: Library Management System

**Вариант 1. Система управления библиотечным фондом**  
**Тип проекта:** серверное приложение (REST API) на Node.js.  
**Цель:** реализовать учёт книг, читателей и выдач, автоматическое обнаружение просрочек и начисление штрафов, статистику и потоковый импорт CSV.

## 1. Объём работ

Нужен работающий backend. Графический интерфейс, роли пользователей, регистрация/авторизация, оплата штрафов, отправка писем, микросервисы и развёртывание в облаке в обязательную часть **не входят**. Проверка API выполняется через Swagger UI, Postman или HTTP-клиент. При желании UI можно добавить позже, не меняя API.

**Рекомендуемый стек:** Node.js (актуальная поддерживаемая LTS), JavaScript с ES-модулями, Express, SQLite + `better-sqlite3`, `zod` для валидации, `node-cron` для расписания, `multer` + `csv-parse` для CSV-импорта, Swagger/OpenAPI 3, Vitest + Supertest для тестов. Если используемые версии библиотек имеют несовместимости, подобрать согласованные версии, не меняя архитектуру.

Причина выбора SQLite: база запускается локально без PostgreSQL и Docker. Хранение должно быть постоянным, не в оперативной памяти. SQL-запросы должны быть параметризованы; изменение наличия книг и выдач — транзакционным.

## 2. Сценарии использования

1. Библиотекарь создаёт книгу и указывает общее число экземпляров; ищет книгу по названию, автору, ISBN и жанру; видит общее и доступное количество.
2. Библиотекарь регистрирует читателя; меняет его статус `ACTIVE`/`BLOCKED`; просматривает историю его выдач.
3. Библиотекарь выдаёт доступную книгу активному читателю: появляется выдача с датой и сроком возврата. Число доступных экземпляров уменьшается.
4. При возврате выдача закрывается, число доступных экземпляров восстанавливается; за возврат после срока вычисляется штраф.
5. Ежесуточная задача переводит невозвращённые выдачи с истёкшим сроком в `OVERDUE` и обновляет накопившийся штраф.
6. Библиотекарь получает топ-5 наиболее выдаваемых книг за период и перечень читателей с текущими просрочками.
7. Библиотекарь отправляет CSV-файл и получает отчёт об импортированных строках, дубликатах и ошибках.

## 3. Структура данных

### 3.1. Book (таблица `books`)

| Поле | Тип | Ограничение |
|---|---|---|
| `id` | integer | PK, автоматически |
| `title` | string | обязательно, 1–255 символов |
| `authors` | array of strings | минимум один автор; в SQLite хранить как JSON в TEXT |
| `isbn` | string | обязательно, уникально, нормализовать удалением пробелов и дефисов |
| `publishedYear` | integer | от 1450 до текущего года + 1 |
| `genre` | string | обязательно, 1–100 символов |
| `totalCopies` | integer | не менее 1 при создании |
| `isArchived` | boolean | по умолчанию `false` |
| `createdAt`, `updatedAt` | datetime | UTC, автоматически |

**Вычисляемое поле ответа API:** `availableCopies = totalCopies − количество выдач данной книги, имеющих статус ACTIVE или OVERDUE`. Не сохранять отдельно, чтобы оно не расходилось с фактическими выдачами.

Нельзя уменьшать `totalCopies` ниже количества невозвращённых экземпляров. Архивную книгу нельзя выдавать. Для ISBN достаточно проверки корректной длины и допустимых символов: 10 или 13 знаков; для ISBN-10 последний символ может быть X. Полную проверку контрольной суммы можно добавить как улучшение.

### 3.2. Reader (таблица `readers`)

| Поле | Тип | Ограничение |
|---|---|---|
| `id` | integer | PK |
| `fullName` | string | обязательно, 2–200 символов |
| `email` | string | валидный email, уникален без учёта регистра |
| `registrationNumber` | string | обязательно, уникален |
| `status` | enum | `ACTIVE`, `BLOCKED`; по умолчанию `ACTIVE` |
| `createdAt`, `updatedAt` | datetime | UTC |

Читатель со статусом `BLOCKED` не может брать книги, но его прежние выдачи можно возвращать. Читатель с текущей просрочкой также не может получить новую книгу, даже если формально статус `ACTIVE`. Максимум одновременно невозвращённых выдач на читателя: **5** (настраиваемая константа).

### 3.3. Loan (таблица `loans`)

| Поле | Тип | Ограничение |
|---|---|---|
| `id` | integer | PK |
| `bookId` | integer | FK на `books` |
| `readerId` | integer | FK на `readers` |
| `loanedAt` | datetime | UTC, время создания выдачи |
| `dueDate` | date | `YYYY-MM-DD` (UTC), дата, до конца которой книгу можно вернуть без штрафа |
| `returnedAt` | datetime/null | дата и время фактического возврата |
| `status` | enum | `ACTIVE`, `OVERDUE`, `RETURNED` |
| `fineAmount` | integer | сумма штрафа **в копейках**, неотрицательна |

Рекомендуемые индексы: `loans(bookId,status)`, `loans(readerId,status)`, `loans(dueDate,status)`, `loans(loanedAt)`; индексы уникальности на ISBN, email, регистрационный номер. Включить SQLite `foreign_keys=ON`.

Выдачи — исторические записи: редактирование или удаление выданной книги через API не предусматривается. Физически удалять книгу или читателя разрешается только при отсутствии любых связанных выдач; иначе вернуть 409 и предложить архивирование книги или блокировку читателя.

## 4. Бизнес-правила

### 4.1. Выдача

`POST /api/loans` с `{ "bookId": 1, "readerId": 2, "dueDate": "2026-11-10" }`.

- Проверить существование книги и читателя.
- Проверить, что книга не архивная, читатель активен, у него нет текущей просрочки и меньше 5 невозвращённых выдач.
- Вычислить доступное количество на основании не закрытых выдач; при 0 вернуть 409.
- Срок возврата по умолчанию — **14 календарных дней с даты выдачи**, в UTC. Явно переданная дата должна быть позднее текущей календарной даты.
- В транзакции повторно проверить доступность и создать запись `ACTIVE`.
- Вернуть 201 с созданной выдачей.

### 4.2. Возврат

`POST /api/loans/:id/return`.

- Если выдача не найдена — 404, уже возвращена — 409.
- Установить `returnedAt`, `status=RETURNED` и окончательный `fineAmount`.
- Не менять `totalCopies`: доступное количество станет больше автоматически благодаря вычислению по незакрытым выдачам.
- Выполнять изменение транзакционно, повторный запрос не должен возвращать одну книгу дважды.

### 4.3. Просрочки и штрафы

**Выбранная для лабораторной тарифная политика:** 10 рублей за каждый календарный день просрочки (**1 000 копеек/день**). Тариф вынести в конфигурацию, не размазывать по коду.

- Сравнение выполняется по календарным датам UTC, а не по полным суткам с момента выдачи.
- Если `returnDate <= dueDate`, просроченных дней 0.
- Если `returnDate > dueDate`, `overdueDays = разность календарных дат в днях`.
- `fineAmount = overdueDays * 1000` в копейках.
- Пример: срок 20.10.2026; возврат 20.10 — штраф 0; возврат 21.10 — 10 руб.; возврат 23.10 — 30 руб.
- Если книга всё ещё на руках, штраф рассчитывается по текущей дате и обновляется при ежедневной проверке. При возврате сумма фиксируется на дату фактического возврата.
- Статус `OVERDUE` присваивается только **невозвращённым** выдачам, у которых `dueDate < today`.
- У записи `RETURNED` статус обратно не изменяется, даже если возврат был поздним; факт опоздания определяется сравнением `returnedAt` и `dueDate`, а штраф остаётся в истории.

Отдельная чистая функция `calculateFine(dueDate, asOfDate)` должна быть легко тестируемой.

### 4.4. Cron

- Задача запускается автоматически **каждый день в 00:05 UTC** через `node-cron`.
- При старте сервера выполнить одну проверку, чтобы после простоя восстановить актуальные статусы.
- Задача обновляет `ACTIVE -> OVERDUE` и штрафы всех невозвращённых просроченных выдач.
- Повторный запуск на ту же дату должен давать тот же результат (идемпотентность).
- Логировать начало, конец, количество обработанных выдач и ошибки.
- Добавить команду `npm run jobs:overdue` для ручного запуска и демонстрации преподавателю. В production не создавать открытый HTTP-эндпоинт запуска служебных задач.
- Для тестов предусмотреть возможность передать в функцию проверки конкретную дату; не зависеть от реальных часов в тестах.

## 5. REST API

Общий префикс: `/api`. JSON в camelCase. Для списков: `page` (от 1), `limit` (от 1 до 100), `total`, `items`.

### Книги

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/api/books` | список, поиск `q`, фильтры `genre`, `author`, `availableOnly`, пагинация |
| GET | `/api/books/:id` | детальная карточка, включая `availableCopies` |
| POST | `/api/books` | добавление |
| PATCH | `/api/books/:id` | редактирование, в том числе архивирование |
| DELETE | `/api/books/:id` | удаление, только если нет связанных выдач |

`q` ищет без учёта регистра по названию и ISBN; поиск по авторам через `author`. Сортировка по названию и затем id обеспечивает стабильную пагинацию.

### Читатели

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/api/readers` | список, поиск `q` по ФИО/email/номеру, фильтр `status`, пагинация |
| GET | `/api/readers/:id` | карточка читателя |
| POST | `/api/readers` | регистрация |
| PATCH | `/api/readers/:id` | редактирование и блокировка |
| DELETE | `/api/readers/:id` | удаление только при отсутствии истории выдач |
| GET | `/api/readers/:id/loans` | история выдач читателя с пагинацией |

### Выдачи

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/api/loans` | список, фильтры `status`, `bookId`, `readerId`, пагинация |
| GET | `/api/loans/:id` | информация о выдаче |
| POST | `/api/loans` | выдать книгу |
| POST | `/api/loans/:id/return` | принять возврат |

### Статистика

**Один обязательный эндпоинт:** `GET /api/stats?from=2026-10-01&to=2026-10-31`.

`from` и `to` — включительно; `from <= to`, даты формата YYYY-MM-DD. Период применяется к топу книг **по дате выдачи** (`loanedAt`), включая уже возвращённые и ещё не возвращённые выдачи.

Возвращать:

```json
{
  "period": { "from": "2026-10-01", "to": "2026-10-31" },
  "topBooks": [
    { "bookId": 1, "title": "Преступление и наказание", "isbn": "9785170906304", "loanCount": 12 }
  ],
  "overdueReaders": [
    {
      "readerId": 2,
      "fullName": "Иванов Иван Иванович",
      "registrationNumber": "R-0002",
      "overdueLoanCount": 2,
      "totalFineAmount": 3000
    }
  ],
  "asOfDate": "2026-10-27"
}
```

Топ: **максимум 5 книг**, сортировка по количеству выдач убыванию, при равенстве — `bookId` возрастанию. `overdueReaders` — читатели, у которых **на текущую дату есть невозвращённые просроченные выдачи**, независимо от периода топа. Вернуть каждого читателя ровно один раз, добавить число его просроченных выдач и суммарный текущий штраф. В запросе для просрочек сравнивать даты, а не полагаться только на устаревший статус.

### Импорт CSV

`POST /api/books/import`, `multipart/form-data`, поле `file`.

Пример содержимого UTF-8 CSV:

```csv
title,authors,isbn,publishedYear,genre,totalCopies
"Преступление и наказание","Фёдор Достоевский",9785170906304,1866,Роман,4
"Соавторская книга","Автор Один;Автор Два",9785000000009,2020,Наука,2
```

- Разделитель колонок — `,`, первая строка обязательно заголовок с полями как в примере; разделитель нескольких авторов внутри поля — `;`. Поля с запятыми и кавычками должны корректно обрабатываться стандартным CSV-парсером.
- Ограничение файла: 10 МБ; принимать `.csv`, UTF-8 с необязательным BOM.
- Обязательно использовать **потоковое чтение**: `fs.createReadStream` и CSV-парсер как stream (через `pipe` или async iteration); запрещено загружать весь CSV через `readFile` или собирать весь массив строк в память.
- `multer` может сначала сохранить загруженный файл в временный каталог, но сам разбор должен быть потоковым; по окончании или ошибке временный файл удаляется.
- Каждую строку валидировать по правилам создания книги, импортировать по одной. Дубликаты ISBN, уже присутствующие в базе или ранее встретившиеся в файле, **пропускать** (не обновлять существующие записи).
- Ошибочная строка не прерывает импорт других строк, если CSV в целом поддаётся разбору. Структурно повреждённый CSV должен приводить к 400.
- Ответ включает `processed`, `created`, `skipped`, `failed`, массив `errors` с номером строки и причиной (не более первых 50 ошибок), а также `errorsTruncated`.
- Считать заголовок отдельно: первая запись данных — строка 2 файла.

Пример:

```json
{
  "processed": 4,
  "created": 2,
  "skipped": 1,
  "failed": 1,
  "errors": [{ "row": 5, "reason": "publishedYear должен быть числом" }],
  "errorsTruncated": false
}
```

## 6. HTTP-статусы и обработка ошибок

- `200` — чтение/изменение/возврат/статистика/результат импорта.
- `201` — успешное создание книги, читателя, выдачи.
- `204` — удалено.
- `400` — неправильные параметры, CSV, валидация; `404` — объект не найден.
- `409` — уникальность, нет экземпляров, повторный возврат, заблокированный читатель, запрет удаления исторических данных, превышен лимит выдач.
- `413` — CSV слишком большой.
- `500` — непредвиденная ошибка.

Единый формат ошибки:

```json
{
  "error": {
    "code": "BOOK_UNAVAILABLE",
    "message": "Нет доступных экземпляров книги",
    "details": {}
  }
}
```

Все входные данные валидировать. Для HTTP-слоя создать централизованный обработчик ошибок; SQL-подстановку строками не использовать. Ошибки сервера логировать, но не отдавать стек-трейсы клиенту.

## 8. Тесты, которые должны проходить

1. Создание книги и уникальность ISBN; получение и фильтрация списка.
2. Создание читателя, уникальность email/registrationNumber и запрет выдачи заблокированному.
3. Выдача уменьшает `availableCopies`; последняя доступная копия выдаётся, а следующая попытка возвращает 409.
4. Возврат восстанавливает доступность, не меняя `totalCopies`; повторный возврат возвращает 409.
5. Лимит 5 активных выдач и запрет выдачи читателю с текущей просрочкой.
6. Расчёт штрафа: 0 дней = 0; 1 день = 1000 коп.; 3 дня = 3000 коп. Проверять на зафиксированных UTC-датах.
7. Плановая задача меняет `ACTIVE` в `OVERDUE` и вычисляет штраф; повторный запуск не даёт двойных начислений; `RETURNED` не затрагивается.
8. Топ-5 за период: учитываются именно факты выдачи, а не остатки; корректные границы периода, лимит 5 и порядок при равенстве.
9. Список просрочивших: каждый читатель один раз, корректное число выдач и сумма штрафов.
10. Импорт: несколько корректных строк, дубликаты, неверная строка, разделитель авторов, кавычки/запятые, кириллица, UTF-8 BOM, пустой файл, большой файл; память не должна расти пропорционально числу CSV-строк.
11. Нельзя удалить книгу/читателя при наличии истории; нельзя установить меньше экземпляров, чем сейчас выдано.

## 9. Демонстрационные данные

Создать `npm run db:seed`, добавляющий не менее 12 книг разных жанров, 8 читателей и 20 выдач разных дат. Включить:

- книгу с 0 доступных экземпляров;
- заблокированного читателя;
- минимум две просроченные и невозвращённые выдачи;
- одну возвращённую вовремя и одну возвращённую с опозданием;
- несколько выдач одной книги, чтобы у топ-5 был осмысленный рейтинг.

Сидирование должно быть повторяемым без создания дубликатов: отдельная команда может очищать **только демо-БД** при явном запуске `db:seed`, но не боевую.

- Документировать, что cron выполняется внутри одного серверного процесса; несколько одновременно работающих инстансов требуют отдельного scheduler/блокировки — это за пределами лабораторной.

## 11. Условия приёмки

Работа завершена, если проект запускается локально из README, все основные эндпоинты реально работают с SQLite, можно провести полный сценарий создания читателя → добавления книги → выдачи → просрочки → возврата → статистики; импорт CSV действительно потоковый; автоматическая задача и ручной запуск работают; тесты проходят; Swagger описывает API; нет подмены работающей логики статическими ответами или хранением только в массивах JS.

## 12. Порядок выполнения с Codex

**Этап 1:** проект, зависимости, SQLite, миграции, слои приложения, `.env`, `/api/health`, команды.  
**Этап 2:** CRUD книг и читателей, поиск, ограничения уникальности, тесты.  
**Этап 3:** выдача, возврат, доступность экземпляров, валидация, транзакции, тесты.  
**Этап 4:** расчёт штрафов, cron, ручной запуск, тесты на фиксированных датах.  
**Этап 5:** статистика, SQL-агрегации, тесты.  
**Этап 6:** потоковый CSV-импорт, отчёт об ошибках, тесты.  
**Этап 7:** OpenAPI/Swagger, demo seed, README, полное тестирование и финальная проверка.

После каждого этапа Codex должен выполнить доступные проверки, перечислить изменённые файлы и кратко объяснить принятые решения. Новые этапы — только после проверки предыдущих.
